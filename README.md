# What Changed in the Room?

Two phone videos of the same small indoor space, taken before and after a few objects were moved,
added or removed. The pipeline reconstructs both captures into one shared 3D representation,
aligns them, finds what changed in 3D, labels each change, and describes it in plain language.

```
before.mp4 ─► frames ─► MASt3R ─┐
                                ├─► align (floor prior + ICP) ─► voxel change detection ─► OWLv2 labels ─► descriptions
after.mp4  ─► frames ─► MASt3R ─┘                                                     └► bird's-eye map + 3D viewer
```

Design choices and their trade-offs are in [DESIGN.md](DESIGN.md).

## Example output

Bird's-eye view of a synthetic desk scene with 4 known changes (floor-aligned; generated by `visualize.py`):

![bird's-eye change map](demo/synthetic/bev.png)

Generated description text (no labeler, so object names are colours only; see DESIGN.md):

```
- moved   - The black object was moved about 1.2 m, to the left.
- moved   - The grey object was moved about 0.9 m, to the right.
- removed - A green object that was there before is no longer present.
- added   - A red object (about 35 cm long) was added.
```

The interactive 3D viewer (`outputs/visualizations/viewer.html`) is written by the pipeline and is not
committed to keep the repo small.

## Installation

Requires Python 3.11 and an NVIDIA GPU for reasonable speed (tested on an RTX 5050 Laptop, 8 GB).

```bash
python -m venv .venv
source .venv/bin/activate          # Windows (Git Bash): source .venv/Scripts/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
git clone --depth 1 https://github.com/naver/mast3r.git third_party/mast3r   # MASt3R/DUSt3R code
```

Model weights (MASt3R metric ViT-L, OWLv2) are downloaded from Hugging Face on first use.
Conda users can run `conda env create -f environment.yml` and then the same `pip` steps for torch and MASt3R.

## Reproduce

Put your captures in `data/before/before.mp4` and `data/after/after.mp4`, then:

```bash
python scripts/run_all.py                 # full pipeline (run time on real videos not yet measured)
python scripts/run_all.py --no-labeler    # skip the OWLv2 labels
```

Each stage is also a standalone script in `scripts/`:

| Stage | Script | Output |
|---|---|---|
| 1. Frame extraction + quality filter | `extract_frames.py` | `data/*/frames/` + `manifest.json` |
| 2. Dense reconstruction (MASt3R) | `reconstruct.py` | `outputs/reconstructions/*.npz`, `*.ply` |
| 3. Alignment | `align.py` | `after_aligned.npz`, `alignment/alignment.json` |
| 3b. No-change control | `make_control.py`, `reconstruct.py`, `align.py` | `control/` (noise floor for detection) |
| 4. Change detection | `detect_changes.py` (`--null` = control) | `change_maps/changes.pkl`, `changes.json` |
| 5. Labels + descriptions | `describe_changes.py` | `descriptions/changes.md`, `changes.json` |
| 6. Visualisation | `visualize.py` | `visualizations/bev.png`, `viewer.html` |

## Capture protocol

Follow the challenge brief (plan section 3):

1. Pick a small indoor area (a desk corner or a living-room corner) and record two 20-45 s clips of it.
2. Between the clips, make 3-6 clear changes: move a chair or box, add an object, remove an object.
3. Walk around the same volume from different viewpoints, with good overlap. Move smoothly, avoid
   backlight, and prefer 1080p at 30 fps in landscape.

## Verification status

| Check | Result |
|---|---|
| MASt3R on the RTX 5050 (3 photos, 512 px, 100 iterations) | runs, 22 s, finite pointmaps and poses |
| Alignment recovers a known rigid perturbation of 25 deg yaw + 0.4 m shift | 2.4 deg / 4.4 cm (target was 2 deg / 5 cm, see DESIGN.md) |
| Change detection vs. synthetic ground truth (4 changes) | 4/4 correct kinds; moved distances 1.2 m / 0.9 m (GT 1.2 / 0.8); added and removed regions sit at the right objects and are object-sized |
| CLI scripts (`detect_changes`, `describe_changes --no-labeler`, `visualize`) | run on the synthetic outputs |
| OWLv2 labeler | runs on GPU; labels are unreliable on the low-resolution synthetic crops |
| Full pipeline on real phone videos | runs end to end (`run_all.py`, exit 0) on the user's two clips; **detects no changes above the noise floor**, so the real-footage result is unresolved (see DESIGN.md section 3) |
| No-change control on the real footage | an independent reconstruction of the same unchanged room gives 17 false regions, the largest 91 voxels; the real pair produces no region larger than that |

`python tests/test_pipeline_glue.py` runs the post-reconstruction stages on ground-truth renders.
It needs no model weights and took 20 s on the RTX 5050 machine.

## Repository layout

```
scripts/        one CLI per pipeline stage, plus run_all.py and the synthetic data generator
src/
  reconstruction/   MASt3R backend (pairwise pointmaps + global alignment)
  registration/     floor estimation, gravity-prior ICP alignment
  change_detection/ ray-carved voxel occupancy, clustering, moved/added/removed classification
  semantics/        OWLv2 labelling of the best camera crop, grounded text
  visualization/    bird's-eye PNG and interactive plotly viewer
tests/          glue test and ground-truth checks
demo/           example outputs that are committed
outputs/        generated (git-ignored)
third_party/    MASt3R checkout (clone, see Installation)
```

## Hardware and time notes

- MASt3R, 512 px, sequential scene graph (swin-2), capped at 40 frames (`--max-frames`): on the real 30 s
  captures, the 300-iteration global alignment took about 55 s per sequence on the RTX 5050. Descriptors are dropped
  per pair to stay within host RAM; with swin-5 and 84-89 frames the run ran out of memory (measured).
- Alignment, change detection and output generation take about 20 s on the synthetic scene (measured).
- OWLv2 loads in about 18 s on the GPU. Per-region labelling time and VRAM use are not yet measured.

## Known limitations

See DESIGN.md, section "Failure cases and limitations", for the full list. The main ones:

- The synthetic captures have rendering artefacts (about 90% of frames have black bands), so they are used
  only for geometric validation, not for a full video run.
- Registration of the flat, feature-poor synthetic floor is approximate (2.4 deg / 4 cm).
- OWLv2 labels need real-resolution crops; the synthetic crops are too small.
